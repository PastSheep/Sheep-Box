# 窗口区域截图模块设计方案（评审稿 v3）

> 状态：**仅设计，未开发**。
> 决策前提（已确认）：目标为**任意第三方窗口**，重点是**游戏窗口的任务区域**；只要求**窗口可见时**可截取；区域由**调用方给坐标**，另提供 **GUI 选区组件**。
> v3 变更：确定设计原则——**能力层提供全量后端，不预判业务用途；业务层按需调用其中一部分**。新增 L0 屏幕直截档与遮挡契约。

## 1. 目标与边界

### 1.1 设计原则

`service/capture` 与 `service/ocr`、`service/sysinfo` 平级，是**纯能力层**：

- **能力给全**：窗口枚举、区域换算（像素 / 归一化）、四种抓取后端、遮挡检测、选区组件，全部提供；不因"当前业务可能只用一种"而删掉其它能力；
- **业务按需**：模块不判断"该用哪个后端"，也不内置业务规则，只提供能力与元数据（`backend`、`degraded`、`occluded`），由消费方选择；
- **能力层不做的事**：不做 OCR、不做定时调度、不做图片编码/落盘、不读写业务配置、不导入 PySide6。

### 1.2 明确不做

| 不做的事 | 原因 | 将来怎么加 |
| --- | --- | --- |
| 独占全屏（Fullscreen Exclusive）抓取 | 绕过 DWM，桌面复制、WGC、BitBlt 全部拿不到 | 无软件解法，只能要求游戏改窗口化/无边框 |
| 截含标题栏的非客户区 | 业务关注客户区内容 | `CaptureOptions.include_frame` 预留 |
| 抓取节奏与调度 | 由消费方控制 | 后端提供 `read_latest()` 供拉取 |
| PNG/JPEG 编码与保存 | service 层不依赖 Qt/Pillow | 上层 `QImage.fromData` 或喂 numpy |
| 区域模板的持久化 | 属业务层 | 业务自己存 `NormalizedRegion` + 窗口标识 |

## 2. 模块布局

```
service/capture/
├── __init__.py          # PEP 562 按需导出：取模型时不加载任何 ctypes 绑定
├── models.py            # WindowInfo / CaptureRegion / NormalizedRegion / ScreenFrame / 能力声明
├── _win32.py            # user32 / gdi32 / dwmapi 绑定与常量
├── windows.py           # 枚举与查询：list_windows / get_window_info / hwnd_from_point / 遮挡检测
├── backends/
│   ├── __init__.py      # 后端注册表 + auto 择优
│   ├── base.py          # CaptureBackend 协议 + BackendCapabilities
│   ├── gdi.py           # L0 屏幕直截 + L1 窗口表面（同一套 GDI 代码，源不同）
│   ├── dxgi.py          # L2 桌面复制
│   └── wgc.py           # L3 单窗口捕获（可选，需第三方包）
└── capturer.py          # WindowCapturer 门面：解析后端 → 抓取 → 校验 → 标记

gui/components/region_picker.py   # 选区覆盖层（GUI 层，只产出坐标）
```

分层：`backends/*` 只依赖 `_win32.py` 与 `models.py`；`capturer.py` 是唯一组装点；`region_picker.py` 只依赖 `windows.py`，不被任何后端绑架。

## 3. 数据模型（`models.py`）

```python
@dataclass(frozen=True)
class CaptureRegion:
    """相对窗口客户区左上角的矩形，单位物理像素。"""
    x: int
    y: int
    width: int
    height: int

    def clamp(self, width: int, height: int) -> "CaptureRegion": ...
    @classmethod
    def full(cls, width: int, height: int) -> "CaptureRegion": ...


@dataclass(frozen=True)
class NormalizedRegion:
    """按比例描述的区域（0~1）。窗口比例固定、分辨率可变时用它。"""
    nx: float
    ny: float
    nw: float
    nh: float

    def to_pixels(self, width: int, height: int) -> CaptureRegion: ...


@dataclass(frozen=True)
class WindowInfo:
    """顶层窗口的可截取性描述。"""
    hwnd: int
    title: str
    class_name: str
    process_id: int
    process_name: str
    client_width: int           # 窗口表面尺寸
    client_height: int
    screen_width: int           # 客户区在屏幕上的实际占位（物理像素）
    screen_height: int          # DPI-unaware 窗口会大于 client_width
    dpi: int
    visible: bool
    minimized: bool
    frame_rect: tuple[int, int, int, int]    # 屏幕坐标（DWM 扩展框优先）
    client_origin: tuple[int, int]          # 客户区左上角屏幕坐标

    @property
    def capturable(self) -> bool: ...
    @property
    def aspect_ratio(self) -> float: ...


@dataclass(frozen=True)
class CaptureOptions:
    backend: str = "auto"            # auto / screen / window / dxgi / wgc
    space: str = "client"            # 区域口径：client（窗口表面像素）/ screen（屏幕物理像素）
    prefer_screen: bool = False      # gdi 内部：本次直接用屏幕帧
    detect_blank: bool = True        # 判黑后尝试下一后端
    verify_occlusion: bool = True    # 抓取前做遮挡校验（仅 screen 口径有意义）
    strict_foreground: bool = False  # 遮挡校验升级为"必须是前台窗口"
    clamp_region: bool = True        # 越界钳制（False 抛错）


@dataclass(frozen=True)
class ScreenFrame:
    """截取结果。像素 BGRA、自上而下、stride == width * 4。"""
    width: int
    height: int
    data: bytes
    region: CaptureRegion
    space: str                   # "client" | "screen"
    backend: str                 # "screen" | "gdi-window" | "dxgi" | "wgc"
    window: WindowInfo
    timestamp: float
    degraded: bool = False       # 是否由回退/降级产生
    occluded: bool = False       # 区域可能被其它窗口覆盖（结果可能含遮挡者内容）


@dataclass(frozen=True)
class BackendCapabilities:
    name: str
    continuous: bool             # 支持连续拉帧
    occluded_ok: bool            # 被遮挡时仍能拿到目标窗口内容
    exclusive_fullscreen_ok: bool
    needs_external_dep: bool
    notes: str
```

要点：

- **`space` 是必须显式传的**：`client` 对应窗口表面，`screen` 对应屏幕实际占位；DPI-unaware 游戏窗口两者不同（1280×720 vs 1600×900），混用必然错位。
- `occluded` / `degraded` 让业务能自己决定"这次结果能不能用"，而不是模块替它判断。
- 不带 Qt/numpy 类型，保持 service 层纯净。

## 4. 能力矩阵（四档，全部提供）

| 档 | 抓取源 | 抗遮挡 | DPI 尺寸陷阱 | 900×700 实测 | 1920×1080 实测 | 依赖 |
| --- | --- | --- | --- | --- | --- | --- |
| **L0 屏幕直截** | `GetDC(NULL)` | ❌ 截到遮挡者 | ✅ 无（全屏幕像素） | 6.1ms | 12.4ms | 无 |
| **L1 窗口表面** | `GetDC(hwnd)` | 部分遮挡可拿到自身内容 | ⚠️ 需区分 client/screen | 1.3ms | 1~3ms | 无 |
| **L2 DXGI 桌面复制** | 显示器输出整帧 | ❌ 整屏内容 | ✅ 无 | <1ms | <1ms | 无 |
| **L3 WGC 单窗口** | DWM 合成该窗口 | ✅ 只含目标窗口 | ✅ 无 | <1ms | <1ms | 需 `windows-capture` / `winrt` |

补充实现（不算独立档）：

- **PrintWindow**：L1 的第二尝试，`PW_RENDERFULLCONTENT`，对老式 GDI 程序有效，对 D3D 窗口通常黑；
- **自动择优**（`backend="auto"`）：合成窗口 → L2/L0；普通窗口 → L1，判黑退 L0；L3 仅在装了包且业务显式要求时使用。

自写 ctypes 路径与第三方封装的对比（实测）：pywin32 的 `CreateCompatibleBitmap` + `GetBitmapBits` 路径在 1920×1080 下为 18.0ms，比自写 DIB（12.4ms）慢约 45%，且返回 bottom-up 需翻转、无法复用缓冲 —— 因此模块实现不引入 pywin32，它只适合做一次性调试脚本。

### 4.1 遮挡契约（L0 / L2 的关键）

`screen` 口径下，被遮挡区域截到的是**遮挡者的内容**，而不是黑图 —— 这种错误最难发现（OCR 只会输出错误文本）。所以：

- `verify_occlusion=True`（默认）：抓取前校验；
  - **弱校验**：区域中心 `WindowFromPoint` → `GetAncestor(GA_ROOT)`，根窗口不是目标 hwnd（且不属于其子窗口）→ 判为遮挡；
  - **强校验**（`strict_foreground=True`）：`GetForegroundWindow()` 的根窗口必须是目标 hwnd（或同进程窗口）。
- 检测到遮挡：默认**不返回内容**，抛 `CaptureOccludedError`；业务若明确接受，可关掉 `verify_occlusion`，此时结果带 `occluded=True` 标记。
- 另需校验：窗口最小化、客户区与屏幕无交集、区域完全越界 —— 这些直接报错，不做"尽力而为"。

## 5. 各后端实现要点

### 5.1 L0 屏幕直截（最低成本档）

1. 校验窗口：`IsWindow` / `IsIconic` / 可见性 / 客户区与屏幕有交集；
2. 遮挡校验（见 §4.1）；
3. `client_origin` 现取（`ClientToScreen`）；
4. 区域换算：`screen_rect = (origin_x + r.x * kx, origin_y + r.y * ky, ...)`，`kx = screen_width / client_width`；
5. `BitBlt(dst, 0, 0, w, h, GetDC(NULL), screen_x, screen_y, SRCCOPY)`；
6. 拷出像素，`space="screen"`，`backend="screen"`。

优点：零判黑逻辑、零 DPI 陷阱、所见即所得；缺点：必须前台且未被遮挡，5~6ms 固定开销，光标会入画。

### 5.2 L1 窗口表面

`GetDC(hwnd)` + `BitBlt`，源偏移直接用 `region.x/region.y`；判黑则按 `detect_blank` 退 L0。失败先试 `PrintWindow`，仍失败再退 L0。

`CreateCompatibleDC` + `CreateDIBSection`（32bpp、`biHeight=-h` top-down），按 `(width, height)` 缓存，`finally` 释放 DC。

### 5.3 L2 DXGI 桌面复制（二期已落地）

1. `CreateDXGIFactory1` → `EnumAdapters1` 逐个取适配器，再用**该适配器**调用 `D3D11CreateDevice`
   （`D3D_DRIVER_TYPE_UNKNOWN` + `BGRA_SUPPORT`）。`DuplicateOutput` 要求设备由 `IDXGIFactory1`
   取到的适配器创建，用 `CreateDXGIFactory` 直接 `E_INVALIDARG`；
2. 在该适配器上 `EnumOutputs` → `GetDesc`，选 `DesktopCoordinates` 覆盖区域中心点的输出；
   `Rotation != IDENTITY`（显示器旋转 90°/270°）直接判不支持；
3. `IDXGIOutput` → `QueryInterface(IDXGIOutput1)` → `DuplicateOutput(device)`；
4. `AcquireNextFrame` → `IDXGIResource` → `QueryInterface(ID3D11Texture2D)` → `CopyResource`
   到 `B8G8R8A8_UNORM` staging → `Map(D3D11_MAP_READ)` 按行读回 → `Unmap` → `ReleaseFrame`；
5. 坐标：屏幕矩形减去输出左上角得到**输出本地坐标**再裁剪，越界（跨屏）抛
   `CaptureUnavailableError`；
6. `DXGI_ERROR_ACCESS_LOST`（分辨率/全屏切换、锁屏）→ 关闭会话、按同一屏幕位置重开一次，
   仍失败抛 `CaptureBackendError`；
7. **首帧丢弃**：复制接口刚建立时第一帧是共享纹理的空帧（实测整张全黑），`open()` 末尾
   拉一次并丢弃，否则业务第一次抓取就拿到无内容的图；
8. 桌面静止时 `AcquireNextFrame` 会超时：同一区域复用上一次结果，换区域且长时间无新帧才
   报 `CaptureBackendError`；
9. 光标不叠加：复制出的桌面图本身不含光标，`GetFramePointerShape` 未使用。

vtable 槽位（本机无 Windows SDK 头文件，按接口声明顺序核对，并与公开实现交叉验证）：

| 接口 | 槽位 |
| --- | --- |
| `IDXGIFactory1::EnumAdapters1` | 12 |
| `IDXGIAdapter::EnumOutputs` / `IDXGIOutput::GetDesc` | 7 / 7 |
| `IDXGIOutput1::DuplicateOutput` | 22（19~21 为三个 1 版方法） |
| `IDXGIOutputDuplication::GetDesc` / `AcquireNextFrame` / `ReleaseFrame` | 7 / 8 / 14 |
| `ID3D11Device::CreateTexture2D` | 5 |
| `ID3D11DeviceContext::Map` / `Unmap` / `CopyResource` | 14 / 15 / 47 |


### 5.4 L3 WGC 单窗口捕获（三期已落地）

1. 由 `windows-capture`（Rust + pyo3，内部走 `IGraphicsCaptureItemInterop::CreateForWindow`）
   按 **hwnd** 建会话，不依赖窗口标题；
2. 捕获在独立线程跑，回调只做「业务是否在等帧 → 是才拷贝一帧」，不取帧时不产生拷贝
   （避免 1 秒抓一次却每秒拷 60 帧）；
3. 帧是**整窗口径**（实测 900×700 窗口得到 902×732，含边框与标题栏），客户区在帧内的
   偏移 = `client_origin - frame_rect`，抓取时按该偏移裁剪，输出 `client` 口径；
4. 画面静止时 WGC 不产帧：抓取先等 50ms 新帧，超时用缓存帧；
5. `open()` 幂等——同一 hwnd 重复调用只刷新尺寸快照，换窗口才重建会话；
6. `close()` 停线程并等待退出，重复调用安全；窗口关闭触发 `on_closed`，之后抓取抛
   `CaptureBackendError`；
7. **不传** `draw_border` 与 `minimum_update_interval`：Win10 不支持这两个设置，传进去
   会话会直接抛异常（实测，见第 19 节）。

依赖取舍：按「性能相近且能避免重复造轮子就引入」的原则，WGC 直接用第三方包，不手写
C++/WinRT ABI；包本身 229KB，且只复用已装的 numpy / opencv，不新增体积。

`wgc` 不参与 `auto` 链：它会常驻一条捕获线程，只在业务明确要求「必须抗遮挡」时显式
指定。


## 6. 游戏场景落地

### 6.1 比例固定 → 归一化区域

任务区域按比例存（如"右上 78%~90% 宽、5%~12% 高"），运行时 `NormalizedRegion(0.78, 0.05, 0.12, 0.07).to_pixels(w, h)`。窗口从 1280×720 切到 1920×1080 无需改配置。少数 HUD 不随分辨率缩放的游戏仍可按像素存，两种都支持。

换算基准：`space="client"` 用 `client_width/height`，`space="screen"` 用 `screen_width/height`。

### 6.2 位置变化

每帧重取 `client_origin`；L2 的复制对象绑定显示器而非窗口，窗口移动不失效，只有跨屏才需换 output。

### 6.3 盘面选择建议（业务侧参考，模块不替它决定）

| 业务需求 | 建议档 |
| --- | --- |
| 每秒 1~2 次检查任务提示、窗口保证前台 | L0 |
| 同样低频，但窗口可能被聊天软件压住 | L1（配合判黑退化） |
| 连续盯帧、要求不撕裂、光标不干扰 | L2 |
| 需要"只含该窗口"的内容，且接受引入依赖 | L3 |
| 不确定 | `auto`，读 `degraded` / `occluded` 决定是否重试 |

### 6.4 硬前提

游戏必须**窗口化或无边框全屏**。独占全屏会绕过 DWM，四档全部失效 —— 检测到独占全屏（窗口矩形覆盖整个输出且 DWM 无合成）时抛 `CaptureUnavailableError`，并提示"请改为无边框窗口模式"。

## 7. DPI 与坐标系

- `client` 口径：窗口表面像素；`screen` 口径：客户区屏幕实际占位；
- `region_picker.py` 内部的 Qt 逻辑坐标按**落点所在屏**的 `devicePixelRatio` 换算，不得跨屏复用同一比例；
- `ensure_dpi_aware()` 调 `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)`，`E_ACCESSDENIED` 视为成功；
- 进程实际不是 per-monitor v2 且窗口 `dpi != 96` 时抛 `CaptureUnavailableError`（否则必然错位或缩小留白）。

## 8. 窗口枚举与查询（`windows.py`）

- `list_windows(...)`：`EnumWindows`（z-order）+ 过滤不可见/无标题/`WS_EX_TOOLWINDOW`/桌面壳（`Progman`/`WorkerW`/`Shell_TrayWnd`）；`frame_rect` 用 `DWMWA_EXTENDED_FRAME_BOUNDS`，退 `GetWindowRect`；
- `get_window_info(hwnd)`：不存在抛 `WindowNotFoundError`；
- `hwnd_from_point(x, y)`：`WindowFromPoint` + `GetAncestor(GA_ROOT)`；
- `region_from_screen(window, rect)`：屏幕矩形 → `client` 口径（按 `client_width/screen_width` 缩放），越界默认钳制；
- `is_occluded(window, region, strict)`：§4.1 的弱/强校验实现。

## 9. GUI 选区组件（`gui/components/region_picker.py`）

只产出坐标，不截图。

- 覆盖虚拟桌面并集（`Qt.Tool | Frameless | StaysOnTop` + `WA_TranslucentBackground`）；
- hover：`hwnd_from_point` 高亮 `frame_rect`，其余 40% 遮罩；
- drag：拉框，实时显示 `物理宽 × 物理高`；松手确认，`Esc` 取消，按住 `Ctrl` 关闭吸附；
- 吸附：距窗边 8px；拖拽 <4px 视为单击 → 返回整个客户区；
- 产出 `PickResult(hwnd, screen_rect, client_region, normalized_region)` —— **三种形态都给**，业务按自己的口径取用；
- 多屏：统一覆盖并集，按落点所在屏的 `devicePixelRatio` 换算。

## 10. 异常契约

`common/exceptions.py` 追加：

```python
class CaptureError(SheepBoxError): ...
class WindowNotFoundError(CaptureError): ...
class WindowNotVisibleError(CaptureError): ...
class WindowOutOfScreenError(CaptureError): ...        # 客户区与屏幕无交集
class CaptureRegionError(CaptureError): ...
class CaptureOccludedError(CaptureError): ...          # 目标区域被其它窗口覆盖
class CaptureUnavailableError(CaptureError): ...       # 环境不满足（DPI / 无桌面 / 独占全屏）
class CaptureBackendError(CaptureError): ...           # 具体后端失败，带错误码与步骤
```

原则：**不返回"看起来正常但内容错"的帧**（黑图、错位、遮挡者内容）；业务明确关掉校验时，才通过 `occluded` 标记把判断权交回业务。

## 11. 性能与线程

实测：1920×1080、i5-12400F、Win10 22H2，40 次中位。

| 档 | 900×700 | 1920×1080 | 连续抓取建议 |
| --- | --- | --- | --- |
| L0 屏幕直截 | 6.1ms | 12.4ms | ≤2 次/秒 |
| L1 窗口表面 | 1.3ms | 1~3ms | ≤3 次/秒 |
| L2 DXGI | <1ms（拷贝已就绪帧） | <1ms | 10~60 次/秒 |
| L3 WGC | <1ms | <1ms | 10~60 次/秒 |
| pywin32 路径（对照） | — | 18.0ms | 不推荐 |

两个实测结论：①GDI 屏幕抓取有 5~6ms 固定开销，区域缩小收益递减（320×240 仍需 6.7ms）；②窗口表面比屏幕快一个数量级，能截到就先用它。

- 全部同步阻塞；L2/L3 另提供 `read_latest()` 拉取最新帧，无帧返回 `None`；
- `WindowCapturer` 支持 `close()` / `with`，释放 DC、DIB、D3D 设备与复制对象；
- 每帧独立 `bytes`，不复用缓冲。

## 12. 测试策略

纯逻辑：`clamp` / `to_pixels`（0~1 边界、最少 1px、取整）/ 口径换算 / 黑图检测 / `len(data) == w*h*4`。

真机（`skipif` 无交互桌面）：

- 记事本：L1 全窗与子区域尺寸正确、非黑；最小化 → `WindowNotVisibleError`；关闭 → `WindowNotFoundError`；
- 浏览器类合成窗口：`auto` 落到 L0/L2，`degraded` 如实标记；
- L0：另一个窗口盖住目标区域 → 抛 `CaptureOccludedError`；前台时成功；
- L2（若可用）：裁剪尺寸与非黑校验；切换分辨率后自动重建一次；
- `auto` 链：mock `dxgi.open` 抛错，断言降级到 L1 → L0。

GUI（offscreen）：QTest 模拟 hover/drag/松手，断言 `PickResult` 三种形态与吸附；Esc 取消；<4px 视为整窗。

## 13. 后端选择由谁定

全局设置页只承载程序级偏好（语言、主题、刷新间隔、渐变锚点）。截图后端属业务技术参数，不进全局设置页。做法：默认 `auto`，业务模块自己的设置里可覆盖，模块只执行。

## 15. 待确认的判断（我先按此实现，可否决）

| 判断 | 选择 | 理由 |
| --- | --- | --- |
| 越界区域 | 默认钳制并写回 `region` | 复用上次坐标时窗口变小不至于整批失败 |
| 遮挡 | 默认校验并抛 `CaptureOccludedError` | 遮挡者内容比黑图更隐蔽，必须显式 |
| 判黑回退 | 默认开启，`degraded=True` | 合成窗口表面常黑 |
| 默认后端链 | 合成窗口 → L2/L0；普通窗口 → L1 → L0 | 兼顾通用与游戏，不让用户先选再试 |
| 区域默认形态 | 归一化优先，像素保留 | 比例固定、分辨率可变 |
| 光标 | 默认不叠加（L2/L3）；L0 无法排除 | 不干扰 OCR |
| 后端选择位置 | 业务设置项，不进全局设置页 | 遵守既定规范 |

## 16. 验收标准

1. 记事本：L1 全窗与子区域尺寸正确、非黑；L0 前台时成功、被遮挡时报 `CaptureOccludedError`；
2. 合成窗口：`auto` 落到可用后端，`degraded` / `occluded` 如实标记；窗口表面判黑必定降级，降级后的屏幕帧若仍无内容则照常返回（游戏加载黑屏属正常画面），由调用方按画面判断；
3. 同一归一化区域在 1280×720 与 1920×1080 下命中同一相对位置（误差 ≤1px）；
4. 窗口移动后无需重新初始化，区域跟随正确；
5. 分辨率切换导致 L2 复制对象失效时自动重建一次；
6. 最小化、销毁、完全越界、屏幕外、独占全屏、被遮挡六类失败均有明确异常；
7. 选区组件可点选整窗与拖拽框选，产出三种形态区域可直接消费；
8. `ruff` / `black` / `mypy` 全绿，新增测试并入全量套件。

## 17. 一期落地记录（实现后回写）

一期按第 14 节落地，与设计稿的差异与取舍如下：

| 项 | 落地做法 | 原因 |
| --- | --- | --- |
| 判黑的「单色」判定 | 只在首像素即暗色时才统计同色占比 | 否则纯白窗口（记事本、白底页面）会被误判成无内容而白白降级 |
| `auto` 链 | L1 → `PrintWindow` → L0（当时无可退的 L2） | 二期 DXGI 未落地；二期已按 4.1 节插入，见第 18 节 |
| 屏幕帧同样无内容 | 记 debug 日志后照常返回 | 游戏加载黑屏是正常画面，抛错会误杀；接受与否由业务判断 |
| 选区组件物理坐标 | 按落点屏的 `devicePixelRatio` 换算，物理原点用「逻辑 × 比例」近似 | Qt 不暴露每屏物理原点；单屏或统一缩放无偏差，混合缩放存在取整级偏差 |
| `include_frame` | 置真即抛 `CaptureUnavailableError` | 首版只做客户区，接口先留 |

真机冒烟（1920×1080、100% 缩放、tkinter 窗口 900×700，红色矩形 600,100–850,300）：

- 全窗：`900×700`，`backend=gdi-window`，`space=client`，非黑；
- 子区域 `(600,100,250,200)`：中心像素 `(204,34,34)`，与填入的 `#cc2222` 一致；
- 归一化 `(0.6667,0.1429,0.2778,0.2857)`：换算为 `(600,100,250,200)`，与子区域一致；
- 窗口销毁后再查询：抛 `WindowNotFoundError`；
- 屏幕口径：尺寸正确，但该次中心像素非纯红（窗口未激活、部分被自身/其它窗口内容覆盖所致）——印证 4.1 节结论，`screen` 路径必须依赖遮挡校验，不能靠像素判断归属。

## 18. 二期落地记录（DXGI 桌面复制）

二期落地 `backends/_dxgi_native.py`（ctypes 手工 COM 层，不引入第三方包）与
`backends/dxgi.py`（`DxgiDesktopBackend`），`auto` 链改为 **L1 → `PrintWindow` → L2 → L0**。
槽位与流程见 5.3，以下是落地时踩到、而设计稿没写到的点。

| 项 | 落地做法 | 原因 |
| --- | --- | --- |
| 设备创建 | 遍历 `IDXGIFactory1` 的适配器，逐个建 device | `DuplicateOutput` 只接受由 `IDXGIFactory1` 适配器创建的 device |
| 首帧 | 打开后拉一帧、读一个像素就丢弃 | 实测不丢弃时**第一次整窗截图中心是纯黑 (0,0,0)**，第二次起正常；同一次运行里子区域与移动后都正确，说明是空帧不是坐标错 |
| 跨屏 | 抛 `CaptureUnavailableError` | 复制图只覆盖一个输出，拼接要多会话，本期不做 |
| 旋转输出 | 抛 `CaptureUnavailableError` | 复制图与屏幕坐标口径不一致 |
| 静止桌面 | 同区域复用上次结果 | `AcquireNextFrame` 超时只说明没有新帧，不代表抓取失败 |
| `wgc` | 仍抛 `CaptureUnavailableError` | 三期；是否引入 `windows-capture` / `winrt` 未定 |

测试改造：`auto` 降级的两条用例（判黑退屏、BitBlt 抛错退屏）原本会先命中真实 DXGI，
已在这两条里把 `DxgiDesktopBackend.capture` 打成不可用；新增「窗口表面判黑后优先用
DXGI」一条，以及 DXGI 后端四条单元用例（输出本地换算、副屏原点、`ACCESS_LOST` 重建、
空区域拒绝）。全量 `pytest` **222 passed / 1 skipped**。

真机冒烟（tkinter 900×700 @ +120,+80，白底 + `#cc2222` 矩形 600,100–850,300，`-topmost`）：

- 整窗连抓三次：`900×700`，`backend=dxgi`，`space=screen`，中心像素均为 `(255,255,255)`
  （首帧丢弃生效）；
- 子区域 `(600,100,250,200)`：中心 `(204,34,34)`，与填入色一致；
- 窗口移到 `+500,+260`（`client_origin` 508,291）：内容不变，**复制会话不重建**；
- 左上角 `(0,0,20,20)`：`(255,255,255)`；
- 20 次连续抓 250×200：**平均 1.06ms/帧**（两次运行 0.96~1.06ms）。

未实测项：分辨率切换导致的 `ACCESS_LOST` 自动重建只在单元测试里用替身会话验证过，
没有在真机上改分辨率跑——改分辨率会改变用户的显示设置，不在本次冒烟范围内。

## 19. 三期落地记录（WGC 单窗口捕获）

### 19.1 依赖决策

| 方案 | 体积 / 形态 | 结论 |
| --- | --- | --- |
| `windows-capture==2.0.1` | 229KB wheel（`cp39-abi3`，Python 3.9+ 通用），Rust + pyo3 二进制 | **采用**：支持按 hwnd 捕获，复用已装的 numpy / opencv，不新增体量 |
| 手写 C++/WinRT ABI | 零依赖，但要自己接 `IGraphicsCaptureItemInterop`、帧池、`ID3D11Texture2D` | 否决：正是「无意义的造轮子」 |
| 不做三期 | — | 否决：「必须抗遮挡」的诉求没有别的档能覆盖 |

按用户确认的原则（性能相近且能省掉重复造轮子就引入），WGC 这一档直接引包；DXGI 那一档
因为已经自写完成、且现成包（`dxcam`）只认主输出、支持面更窄，维持自写。

### 19.2 Win10 平台限制（实测撞到）

本机 Win10 Pro 22H2 19045.7807 上，构造会话时传下列参数会让 `start_free_threaded()`
直接抛异常：

| 参数 | 报错 |
| --- | --- |
| `draw_border=False` | `Toggling the capture border is not supported by the Graphics Capture API on this platform` |
| `minimum_update_interval=33` | `Setting a minimum update interval is not supported by the Graphics Capture API on this platform` |

两者都是 Win11 才支持的设置项。实现里都不传：Win10 没有捕获边框（也就没有「黄框」问题），
Win11 会在被抓窗口外画一圈黄框，这是 API 既定行为，关不掉。

### 19.3 真机冒烟

tkinter 900×700 @ +150,+120，白底 + `#cc2222` 矩形 600,100–850,300：

- 窗口帧 `902×732`（=`frame_rect`），客户区偏移 `(1, 31)`；
- 整窗：`900×700`，`backend=wgc`，`space=client`，中心 `(255,255,255)`；
- 子区域 `(600,100,250,200)`：中心 `(204,34,34)`；
- **遮挡**：用一块 500×400 不透明黑窗盖住目标区域后，仍为 `(204,34,34)`——这是本档的
  唯一价值所在，其它三档此时都会拿到黑窗或遮挡者内容；
- 窗口移到 `+420,+240`（`client_origin` 428,271）：内容不变；
- 250×200 连续 20 次：**平均 6.04ms/次**（含等待新帧；DXGI 同区域 1.06ms，WGC 更慢但
  抗遮挡）。
